Build your resume

How many projects, structure, bullet style, project ideas — invent your content, borrow only the shape.

First internship shape

You don’t need five jobs. You need a one-page resume: education, maybe one Experience line (EPICS / research), and two solid projects (hard max 3). Every strong bullet = what you built + tools + a number. Copy the shape from strong Purdue SDE résumés — never their sentences, metrics, or project names.

How many projects

CountWhenWhy
2 (recommended)DefaultRecruiters skim 6–10 seconds. Two deep projects beat five shallow labs.
3All finished, demoable, different axesA third only helps if it adds a new skill signal.
1Plus real Experience linesOne flagship + EPICS/research often beats three solo hacks.
4+Almost neverReads as class-lab dumping.

Bullet style (the real skill)

Verb + what you built/changed + with which tech + so that what improved (number)

  • Bad: “Worked on a robotics navigation project using ROS.”
  • Better: “Implemented ROS 2 Nav2 stack in Gazebo for a differential-drive robot, cutting manual teleop demos from 10 minutes to a repeatable 60-second scripted run.”
  • Bad: “Used AWS for a class project.”
  • Better: “Deployed a Python API on AWS Lambda behind API Gateway with S3 artifact storage, handling 200 test requests/min in load checks.”

Project ideas (pick primary + secondary)

Campus / utility

  • Course / exam conflict helper · study-group matcher · dining/bus wait-time dashboard (public data only)

Cloud pipelines (Amazon/Microsoft language)

  • Photo/log ingest: S3 → Lambda → DynamoDB/Postgres → status API
  • CI notifier (GitHub Action → Discord/Slack)
  • Batch CSV → cleaned Parquet on S3

LLM / agent tools (build original)

  • Syllabus Q&A with RAG + page citations
  • Campus FAQ agent that calls tools
  • Code-review helper for CS 180-sized repos

Robotics-friendly (frame as software)

  • ROS 2 + Gazebo Nav2 with scripted mission + demo
  • YOLO vision pipeline with mAP / precision on your set
  • Sim-to-metrics logger → S3 + web chart (bridges robotics ↔ cloud SDE)

Selection rule: Primary = interview story. Secondary = different axis (e.g. ROS + thin AWS). Skip anything you can’t demo. Lead with software nouns for SDE recruiters.

What else belongs

  • High: EPICS, research, Data Mine, SURF, TA, shipped hackathon, merged OSS PRs
  • Medium: 4–6 course names, GPA if ≥ ~3.5, technical org leadership with a software outcome
  • Skip: Soft clubs with no software, high school (usually), Objective paragraph, colorful ATS-breaking templates

First draft workflow (90–120 min)

  1. Dump everything into a messy doc.
  2. Keep only items that prove coding + ownership.
  3. Force the skeleton into one page.
  4. Rewrite every bullet with Verb + Tech + Metric.
  5. Export PDF; put link in the father–son tracker.
  6. Align LinkedIn headline/About with the same story.
  7. Tailor one line of Skills order per application.
Anti-plagiarism

Read each bullet aloud. If it could appear on someone else’s LinkedIn from the Purdue pack, rewrite until only you could claim it. Inspiration ≠ plagiarism. Pattern library only — do not invent LinkedIn people beyond what’s in the source walkthrough.

Resume checklist

Before you apply0 / 0
  • One page, readable font (~10–11 pt)
  • 2 projects (or 1 project + ≥1 Experience line)
  • ≥3 bullets with real numbers I can defend
  • GitHub (or live demo) in header and on each project
  • LinkedIn headline matches (“Seeking Summer 2027 SDE”)
  • Skills row includes languages I can interview in
  • No copied sentences from public résumés
  • I can explain my flagship in 60 seconds (Verb + Tech + Metric)
