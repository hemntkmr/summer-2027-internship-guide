How we track

Proof rules, Dad review line, and weekly log fields. Done = a link Dad can open.

The whole rule

Status may be Done only if the Output link opens and matches the proof rule. No link → not Done.

How to use

  1. Copy the weekly log into a shared Google Doc, Notion, or Sheets.
  2. Each week, duplicate the Weekly log (or add a tab named YYYY-MM-DD).
  3. Son fills Status and Output link / proof before Sunday night.
  4. Father uses only the Dad review line at the bottom of that week.
Shared folder suggestion (Google Drive)

Internship Prep 2026-27 / Weekly Logs / Proofs
Son drops PDFs, screenshots, and short demo videos into Proofs; paste sharing links into the tracker.

What “done” means (proof rules)

Task typeDone output (son must submit ONE)
ResumeLink to PDF or Google Doc (view access for dad). Filename like Resume_v2_2026-10-12.pdf.
ApplicationScreenshot of confirmation page or forwarded confirmation email. Include company + job ID.
ReferralCopy of email to referrer plus confirmation that referral was submitted (screenshot or dad’s reply “it’s in”).
LeetCode / OAList of problem numbers (or titles) + result (e.g. Accepted 12ms). Paste or short Doc link.
Project workGitHub repo link and either a 30–90 sec demo video or README “Demo” with GIF/screenshot.
Outreach emailFull sent email (To / Subject / Body) in a Doc, or screenshot of Sent folder.
Open-source PRURL of the pull request (and issue number if any).
Fair / networkingShort note: date, 5+ company names, one follow-up sent (link).
OtherOne artifact link a stranger could open and verify in under 30 seconds.

Status values (use exactly): Not Started · In Progress · Done

Dad review line (every week)

Open this week’s table. For every row marked Done, click the Output link once. If the proof matches the task type, leave it. If anything is Done without a working proof, change it to In Progress and text your son one sentence: “Need proof link for [task].” Then stop — no other coaching required unless he asks.
